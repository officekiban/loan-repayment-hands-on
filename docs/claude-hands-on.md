# Claude Code × 成果物照合ハンズオン

- 標準: **45分**
- 短縮: **30分**（実装修正を省略し、判断引継ぎまで）
- 発展: **+15分**（既存のステージング確認と本番承認フローを観察）
- 対象: Claude Codeを使い、複数成果物の不整合を検出して人間判断へ安全に引き継ぐ体験
- 使用情報: ダミー値・公開情報のみ

> この資料のチェック状態を保存したい場合は、`docs/claude-hands-on.html`をブラウザで開く。Markdown版と同じ進行内容に、端末内だけで保存される進捗チェックを付けている。

## 今日のゴール

```text
成果物を読む → 根拠を照合する → 判断できない点で止まる
        → 人が決める → 同じ変更でそろえる → 証拠を確認する
```

完成コードの速さではなく、Claudeが根拠不足を検知し、独断で埋めず、人間が判断できる形に整理できるかを確認する。

## 0. 開始前チェック（5分）

- [ ] 実在の顧客情報、融資条件、メールアドレス、内部資料を使っていない
- [ ] Cloudflare/GitHubのTokenやSecretを端末へ貼り付けていない
- [ ] このリポジトリのルートにいる
- [ ] `node --version`、`npm --version`、`claude --version`が成功する
- [ ] `npm ci`と`npm run check`が成功する
- [ ] Gitの現在ブランチと差分を把握している

```powershell
npm ci
powershell -ExecutionPolicy Bypass -File scripts/preflight-claude-hands-on.ps1
```

ガイドとシミュレータを開く場合:

```powershell
powershell -ExecutionPolicy Bypass -File scripts/open-claude-hands-on.ps1
```

Claude CodeはPlan Modeから始める。課金契約、ログイン方式、組織ポリシーは利用者側で確認し、このハンズオンから新規に有効化しない。

```powershell
claude --permission-mode plan
```

## 1. 全体をつかむ（5分）

最初は変更させず、Claudeが現在の事実と文書の役割を分けて説明できるかを見る。

### Prompt 1 — 現状把握

```text
このリポジトリのハンズオンを開始します。まだファイルを変更しないでください。

README.md、docs/basic-design.md、docs/test-spec.md、
app/loan-repayment-simulator.html、.github/workflows/release.yml、
docs/cicd-setup.mdを読んで、次を簡潔に整理してください。

1. このモックの目的と非対象
2. 設計・テスト・実装・CI/CDの関係
3. 現在確認できる事実
4. まだ証拠がなく判断できないこと

重要な説明にはファイル名とIDを付けてください。
```

- [ ] 目的と非対象が分離された
- [ ] 設計・テスト・実装・CI/CDの関係が説明された
- [ ] 事実と未確認事項が混ざっていない

## 2. 成果物を照合する（10分）

AIに修正案を急がせず、根拠の一致・不一致・不足を一覧化させる。

### Prompt 2 — 整合性レビュー

```text
引き続きファイルは変更しないでください。

入力条件、返済方式、据置期間、端数処理、表示結果について、
基本設計、テスト仕様、実装を相互照合してください。

結果は「一致」「不一致」「テスト不足」「実装未反映」に分け、
各項目にファイル名、IDまたは該当箇所、短い根拠を付けてください。
上位根拠がなく正解を決められない項目は、推測で解消せず
「人間判断待ち」と明記してください。
```

- [ ] 少なくとも3種類の成果物が相互照合された
- [ ] 重要な論点にファイル名とIDが付いた
- [ ] 不一致と単なる未実装が区別された
- [ ] Claudeが根拠のない正解を選ばなかった

## 3. 人間判断へ引き継ぐ（8分）

次に必要なのは「どちらが正しいと思うか」ではなく、人が判断できる材料である。

### Prompt 3 — 判断メモ

```text
人間判断が必要な論点だけを、1件の判断メモにしてください。

- 論点
- 衝突している根拠
- それぞれを採用した場合に変わる成果物
- 現時点で決められない理由
- 人間への質問（1問）
- 回答が得られるまで保留する作業

推奨を出す場合は、事実とは分け、根拠と留保を明記してください。
まだ実装しないでください。
```

- [ ] 衝突する根拠が並べて示された
- [ ] 影響する成果物が列挙された
- [ ] 人間への質問が1問に絞られた
- [ ] 回答前の変更が保留された

### 人間のチェックポイント

ここで進行役または業務責任者が、採用・修正・保留を明示する。根拠が足りない場合は「保留」が正しい。AIを動かすためだけの決定はしない。

- [ ] 判断者を記録した
- [ ] 判断内容または保留を記録した
- [ ] 判断根拠を記録した

## 4. 判断後にそろえる（12分）

人間が明示的に決めた場合だけ実施する。保留の場合は変更せず、課題票の形で終了する。

### Prompt 4A — 採用または修正

```text
人間判断を伝えます。

判断: [ここに採用する規則を書く]
判断者: [役割名]
根拠: [承認済みの根拠を書く]

この判断に合わせ、影響する基本設計、テスト仕様、実装、
テスト期待値を同じ変更内で整合させてください。
app/index.htmlは直接編集せず、編集元を直してnpm run buildで生成してください。

変更後にnpm run checkとgit diff --checkを実行し、
変更ファイル、確認結果、未解決事項を報告してください。
push、deploy、Secret操作はしないでください。
```

### Prompt 4B — 保留

```text
人間判断は「根拠不足のため保留」です。実装とテスト期待値は変更しないでください。

論点、確認先、必要な根拠、影響範囲、再開条件を、
そのまま課題票へ貼れる形式でまとめてください。
現在のGit差分も確認し、意図しない変更がないことを報告してください。
```

- [ ] 人間の回答がプロンプトに明記された
- [ ] 影響成果物が同じ変更で整合した、または保留のまま維持された
- [ ] 生成物を直接編集していない
- [ ] push・deploy・Secret操作をしていない

## 5. 証拠を確認して閉じる（5分）

```powershell
npm run check
git diff --check
git status --short --branch
git diff --stat
git diff
```

### Prompt 5 — 最終レビュー

```text
最終レビューをしてください。新しい変更は加えないでください。

1. 人間判断と変更内容の対応
2. 設計・テスト・実装の整合
3. 実行した検証と結果
4. 残る留保と未確認事項
5. GitHubへ反映する前に人が見るべき点

成功したコマンドや画面表示を、業務仕様が正しい証拠とは扱わないでください。
```

- [ ] `npm run check`が成功した
- [ ] `git diff --check`が成功した
- [ ] 差分を人が読んだ
- [ ] 未解決事項と人間の次行動が明記された
- [ ] 完了・保留のどちらかを宣言した

## 発展: CI/CDの観察（+15分）

既存環境を使う場合だけ行う。Claudeに認証情報を渡さず、GitHub ActionsとGitHub Environmentの画面は人が操作する。

1. 同一コミットから配布物が固定されることを確認する。
2. ステージングURLとスクリーンショットを人が確認する。
3. `production` Environmentが人間承認待ちで停止することを確認する。
4. 承認または拒否は人が判断する。

- ステージング: <https://loan-hands-on-staging.pages.dev/>
- 本番: <https://loan-hands-on-production.pages.dev/>

デプロイ成功やスクリーンショット生成は、計算ルールの妥当性を証明しない。

## 安全境界

- 実在の融資判断には使わない。
- ClaudeへToken、Secret、内部情報、個人情報を入力しない。
- API課金や有料プランを、このハンズオンのために新規有効化しない。
- Claudeの許可確認を無効化しない。
- 本番承認、push、merge、deployは人が明示的に行う。
- `docs/operator-story.md`は進行役用であり、参加者へ先に見せない。
