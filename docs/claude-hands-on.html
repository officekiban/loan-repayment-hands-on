01 · 10 MIN

テスト仕様書兼成績書をレビュー

下のプロンプトをそのまま貼り付けます。

docs/test-spec.mdを、テスト仕様書兼成績書としてレビューしてください。
docs/basic-design.mdとapp/loan-repayment-simulator.htmlを照合し、まだファイルは変更しないでください。

次の観点で、問題ごとに「指摘」「根拠となる文書名と項目名」「見逃した場合の影響」「追加または修正すべきテスト」を示してください。

- 基本設計書とテスト仕様書兼成績書の矛盾
- 基本設計書に書かれているのにテストされていない仕様
- 境界値テストの漏れ
- テスト結果だけでは正しさを判定できない項目

番号やIDだけでなく、「基本設計書の毎月利息」「テスト仕様書兼成績書の利息端数」のように、何の項目か分かる書き方にしてください。
重要度の高い順に並べてください。
答え合わせ
1・2は文書を突き合わせれば分かる指摘です。3・4は、書かれていないテストまで考える一段深い指摘です。

1・2：基本設計書とテスト仕様書兼成績書を突き合わせる

3・4：「何をテストすべきか」まで一段深く考える

02 · 15 MIN

返済年数上限を30年へ変更

レビューが終わったら、続けて貼り付けます。

仕様変更です。返済年数の上限を100年から30年へ変更してください。

次を同じ作業でそろえてください。

1. docs/basic-design.mdの入力項目「返済年数」
2. docs/test-spec.mdの返済年数境界値テスト
   - 30年は受け付ける
   - 31年は入力エラーにする
3. app/loan-repayment-simulator.htmlの入力上限とエラーメッセージ
4. npm run buildで生成するapp/index.html

利息端数処理の不整合は今回の変更対象ではありません。
実装後にnpm run checkを実行し、変更箇所と確認結果を報告してください。

完了確認

03 · 15 MIN

Gitでテスト環境・本番環境へ反映

変更をコミットして送るところまでClaude Codeに任せ、マージと本番承認は人が行います。

ここまでの変更をGitで共有できる状態にしてください。

1. git statusとgit diffで変更内容を確認する
2. 現在の変更を保持したまま、hands-on/repayment-years-30-日時 という新しいブランチを作る
3. このclaude-demoフォルダ内の変更だけをステージする
4. 変更内容が分かるメッセージでコミットする
5. git push -u origin HEADでGitHubへ送る

mainへのマージは行わず、実行したコマンド、コミットID、Pull Requestを作るためのURLを報告してください。
Pull Request自動検証後にmainへマージ
テスト環境URLと画面キャプチャを確認
本番環境人が承認して同じ成果物を反映

Pull Requestから本番反映まで

  1. Claudeが示したURLからPull Requestを作る。
  2. 自動検証の成功を確認してmainへマージする。
  3. GitHub ActionsのStaging review and production approvalを開く。
  4. テスト環境のURLと画面キャプチャを確認する。
  5. productionの承認待ちで、確認した人が承認する。
  6. 本番環境への反映成功と画面を確認する。
