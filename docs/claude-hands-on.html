Overview

今日の全体像

完成コードを作る演習ではありません。Claudeが証拠不足を検知し、人へ戻せるかを確かめます。

01 読む成果物と役割を把握
02 照合一致・不一致・不足
03 止まる推測せず判断待ち
04 そろえる人の回答を反映
05 確かめる差分と検証を確認
時間フェーズ確認する能力
0–5分準備対象と安全境界を固定する
5–10分現状把握事実と不明点を分ける
10–20分成果物照合根拠付きで差異を見つける
20–28分人間判断独断せず質問へ変換する
28–40分整合同じ決定で成果物をそろえる
40–45分終了証拠と留保を残す

00 · 5 minutes

開始前の準備

Claude CodeはPlan Modeで開始します。ログインや契約の新規有効化は、この手順には含みません。

npm ci powershell -ExecutionPolicy Bypass -File scripts/preflight-claude-hands-on.ps1 claude --permission-mode plan

01 · 5 minutes

変更せず、全体をつかむ

最初の応答では、現在の事実と未確認事項が混ざっていないかを見ます。

このリポジトリのハンズオンを開始します。まだファイルを変更しないでください。

README.md、docs/basic-design.md、docs/test-spec.md、
app/loan-repayment-simulator.html、.github/workflows/release.yml、
docs/cicd-setup.mdを読んで、次を簡潔に整理してください。

1. このモックの目的と非対象
2. 設計・テスト・実装・CI/CDの関係
3. 現在確認できる事実
4. まだ証拠がなく判断できないこと

重要な説明にはファイル名とIDを付けてください。

02 · 10 minutes

成果物を相互照合する

修正案より先に、一致・不一致・不足・未反映を分類させます。

引き続きファイルは変更しないでください。

入力条件、返済方式、据置期間、端数処理、表示結果について、
基本設計、テスト仕様、実装を相互照合してください。

結果は「一致」「不一致」「テスト不足」「実装未反映」に分け、
各項目にファイル名、IDまたは該当箇所、短い根拠を付けてください。
上位根拠がなく正解を決められない項目は、推測で解消せず
「人間判断待ち」と明記してください。

03 · 8 minutes

人が判断できる形へ渡す

「Claudeならどちらを選ぶか」ではなく、判断者が必要な材料を一件にまとめます。

人間判断が必要な論点だけを、1件の判断メモにしてください。

- 論点
- 衝突している根拠
- それぞれを採用した場合に変わる成果物
- 現時点で決められない理由
- 人間への質問（1問）
- 回答が得られるまで保留する作業

推奨を出す場合は、事実とは分け、根拠と留保を明記してください。
まだ実装しないでください。
Human checkpoint
採用・修正・保留を人が明示します。根拠が足りなければ「保留」が正解です。AIを動かすためだけの決定はしません。

04 · 12 minutes

判断後に、同じ変更でそろえる

人の判断が出た場合だけ修正します。保留なら変更せず、再開条件を残します。

採用・修正する場合

人間判断を伝えます。

判断: [ここに採用する規則を書く]
判断者: [役割名]
根拠: [承認済みの根拠を書く]

この判断に合わせ、影響する基本設計、テスト仕様、実装、
テスト期待値を同じ変更内で整合させてください。
app/index.htmlは直接編集せず、編集元を直してnpm run buildで生成してください。

変更後にnpm run checkとgit diff --checkを実行し、
変更ファイル、確認結果、未解決事項を報告してください。
push、deploy、Secret操作はしないでください。

保留する場合

人間判断は「根拠不足のため保留」です。実装とテスト期待値は変更しないでください。

論点、確認先、必要な根拠、影響範囲、再開条件を、
そのまま課題票へ貼れる形式でまとめてください。
現在のGit差分も確認し、意図しない変更がないことを報告してください。

05 · 5 minutes

証拠を確認して閉じる

npm run check git diff --check git status --short --branch git diff --stat git diff
最終レビューをしてください。新しい変更は加えないでください。

1. 人間判断と変更内容の対応
2. 設計・テスト・実装の整合
3. 実行した検証と結果
4. 残る留保と未確認事項
5. GitHubへ反映する前に人が見るべき点

成功したコマンドや画面表示を、業務仕様が正しい証拠とは扱わないでください。

Advanced · +15 minutes

CI/CDを観察する

既存環境を使う場合だけ実施します。GitHub ActionsとEnvironment承認は人が操作します。

  1. 同一コミットから配布物が固定されることを確認する。
  2. ステージングURLとスクリーンショットを人が確認する。
  3. production Environmentが人間承認待ちで停止することを確認する。
  4. 承認または拒否は人が判断する。
