# Claude Code ハンズオン運営メモ

## 進行

1. 参加者が`docs/test-spec.md`をClaude Codeへレビューさせる。
2. Claudeの指摘を`docs/claude-hands-on.md`の答え合わせと照合する。
3. 返済年数上限を100年から30年へ変更させる。
4. 設計、テスト仕様書兼成績書、編集元HTML、生成HTMLが同じ変更になったことを確認する。

## レビューで必ず出したい4点

1・2は基本設計書とテスト仕様書兼成績書を突き合わせれば分かる。3・4は、記載内容を読むだけでなく「正しさを保証するには何をテストすべきか」まで考える一段深い指摘とする。

### 文書の突き合わせで分かる指摘

#### 1. 利息端数処理の矛盾

- 基本設計書の「毎月利息」: 1円未満を切り捨てる。
- テスト仕様書兼成績書の「利息端数」: 100.5円を四捨五入して101円とする。
- 正とする規則は、このレビューでは決めない。

#### 2. 元利均等テストの期待結果が強すぎる

- テスト仕様書兼成績書の「元利均等」: 返済開始月と最終回が必ず同額になる。
- 基本設計書の「元金の端数」: 端数調整により最終回が通常月と異なる場合がある。
- 現在のテストだけでは最終月調整の正しさを判定できない。

### テスト設計まで考えて分かる指摘

#### 3. 元金最終月調整の直接テストがない

不足している確認は次の二つ。

- 全行の元金合計が借入金額と一致する。
- 最終行の返済後残高が0円になる。

#### 4. 返済年数の境界値テストがない

基本設計書の入力項目「返済年数」は1年以上100年以下だが、1年、100年、0年、101年のテストがない。後半の仕様変更では、30年が正常、31年がエラーとなるテストへ置き換える。

## 仕様変更の完了条件

- 基本設計書の入力項目「返済年数」が1年以上30年以下。
- 画面入力の`max`が30。
- 入力チェックとエラーメッセージが30年上限。
- テスト仕様書兼成績書に30年正常、31年エラーのケースが追加される。
- `app/index.html`が編集元から再生成される。
- `npm run check`が成功する。

利息端数処理は変更対象に含めない。
